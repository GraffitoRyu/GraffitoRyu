# SVG 내부 CSS 렌더링 실험

현재 프로필·Figma 시안을 교체하지 않는 기술 실험이다. 모든 노드와 설명은 시험용 placeholder이며, v1.1 SUMMARY의 내용·구성은 미확정이다.

GitHub 공개 프로필에서 실측한 README 콘텐츠 폭 846·831·575·293·263 CSS px을 로컬 외부 `<img>`에 적용했다. macOS WKWebView, 비영구 데이터 저장소, DPR 2에서 확인했으며 사용자 브라우저를 조작하지 않았다.

| 대조본 | 결과 |
|---|---|
| `fixed-viewbox.svg` | 내부 미디어 쿼리는 이미지 표시 폭에 따라 분기하지만 글자·도형은 함께 축소된다. |
| `fluid-css.svg` | `viewBox`를 없애도 루트 폭 900px을 고정하면 축소가 남는다. CSS 세로 재배치가 외부 이미지 높이를 늘리지 않아 내용이 잘린다. |
| `percent-width.svg` | 루트 폭 100%, 고정 높이 440px, `viewBox` 없음. 외부 이미지 폭 900 지정과 `max-width:100%`에서 내부 CSS로 가로·세로 배치를 전환한다. 글자와 16px 기준 블록이 비례 축소되지 않는다. |

`render-check.swift`가 15개 이미지의 로드와 실제 표시 폭을 검사하고 결과·스크린샷을 저장한다. `render-result.json`은 로컬 WebKit 측정값이다. `proof-*.png`은 대조본 전체, `responsive-*.png`은 퍼센트 폭 SVG의 실제 렌더링이다. 846·293·263px 결과의 기준 블록은 픽셀 검사에서 각각 16×16 CSS px이었다.

퍼센트 폭 대조본의 외곽선은 1px stroke가 이미지 경계 안에 놓이도록 맞췄다. 같은 세 폭에서 오른쪽 경계 픽셀도 확인했다.

내부 CSS만으로 폭별 재배치와 글자 크기 유지가 가능함을 확인했다. 하단 설명도 SVG 안에 제공할 수 있으므로 Markdown 분리는 필수가 아니다. 다만 현재 높이는 440px로 고정되어 넓은 화면에 여백이 남는다. 폭별 높이와 실제 관계도 내용의 최적화는 완료되지 않았다.

실제 GitHub 게시·이미지 프록시·다른 브라우저 엔진·실제 휴대폰·라이트/다크 테마·200% 확대·긴 문구/RTL은 검증하지 않았다. 로컬 이미지 모드 결과를 GitHub 적용 완료로 간주하지 않는다.

기존 README·Activity·Figma는 변경하지 않았다. 실험 자료는 이 작업의 담당 Codex가 후속 검토용으로 보존한다. 후속 작업은 미확정 Workflow의 관계 누락과 In practice의 설명 중복을 함께 정리하고, 표시 높이와 실제 호스팅을 검증하는 일이다.
